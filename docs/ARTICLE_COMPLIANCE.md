# Сверка со статьёй

Что в коде сделано по статье [DAMP](DAMP.pdf) и её [продолжению](DAMP_continuation.md), а что — доработка или вне статьи. Документ идёт по семи этапам пайплайна.

**Обозначения.** §6.5 — параграф статьи, П.5 — раздел продолжения (П.1–П.9). Пути вида `system/damp/…` даны внутри системного слоя (`system/damp/`). Оценки в столбце «Как сделано»:

- **по статье** — так, как в источнике;
- **доработка** — источники молчат или допускают выбор; решение наше, причина указана;
- **вне статьи** — части, которых в статье нет совсем (данные MNIST, мерки, рисунки).

| Понятие | Источник | Где в коде | Как сделано |
|---|---|---|---|
| Широкие перекрывающиеся детекторы, слои от широкого к узкому | §4.1, §4.2, §4.5 | `Encoder`, `geometric_detector_layers` (`system/damp/encoding/damp_encoder.py`) | по статье |
| Один случайный бит на детектор; цветовые полосы по слоям | §3.2, §4.2.1, §5.14 | там же | по статье |

| Коды координат слиты OR в общий код 512 бит (команда `layout`) | §2.2.1, §2.2.3 | `_build_encoder` (`system/damp/encoding/mnist_codes.py`) | по статье: статья допускает и слияние, и склейку |

| Код окна: биты места OR + код признака, изменённый маской детектора места | П.4, П.5 | `PositionBindingEncoder` (`system/damp/encoding/position_binding.py`) | по продолжению |
| Пулинг в области детектора места | П.5 | там же, `LADDER_BINDING_POOLING = "strongest"` | доработка: продолжение оставляет выбор |
| Маска — XOR с адресом бита (перестановка) | П.5 | там же, `LADDER_BINDING_MASK = "address"` | доработка |
| Длина содержания — степень двойки под плотность 0.2; лишние биты — слиянием цветов | §2, §3.3; П.7 | там же | по статье и продолжению |

**Отклонения:**

- **Маска по адресу бита вместо буквального XOR.** П.5 говорит «XOR маски с кодом» и сам предупреждает, что XOR может менять плотность. Буквальный XOR оставлял биты признака на своих местах и насыщал код: голосование 10.0 %. Перестановка адреса `i → i ⊕ m` сохраняет число единиц: 65.2 %.
- **Пулинг "strongest".** Из области берётся самый сильный элемент. Объединение (`"max"`) переполняет код окна: карта третьего уровня слипается до 799 точек, голосование 49.8 %.
- **Место — внутри окна, а не на картинке** (§7.1.4.1). В коде окна нет абсолютного места, поэтому цифра узнаётся в любом месте кадра. Сдвиг на (3, 5) клеток даёт тот же отклик (косинус 1.0).

|---|---|---|---|

| Дальняя энергия `φ = Σ s·d` по всему пространству | §5.5.1 | `LAYOUT_SMOOTH_PINWHEELS = False` | по статье |
| Гауссово ядро дальней фазы, фиксированный λ, слабый отжиг | — | `LAYOUT_SMOOTH_PINWHEELS = True` (**стоит по умолчанию**) | доработка |
| Расписание радиуса и λ по доле обменов | §7.1.7 | `LayoutParameterTuner` (`system/damp/layout/mnist_layout.py`) | по статье в режиме статьи |
| Энергия точки `Ê` и качество `Ē` | §5.7, §5.8 | `Layout.point_energies` | по статье |
| Подмножество для дальней энергии | §5.9.4 | там же | по статье, только для наборов больше 100 000 точек |
| Сходства на лету, расчёт на видеокарте | §5.9.5, §5.12 | `system/damp/layout/*` | по статье |
| Пустые ячейки — 15 % от числа точек | §7.1.6 (около 15 %) | `LAYOUT_EMPTY_RATIO = 0.15` | по статье; замер: 50 % не лучше (см. ниже) |
| Почти одинаковые коды окон сливаются к образцу | §2.2.4 | `LeaderDictionary` (`system/damp/layout/code_dictionary.py`) | доработка: карта уровня — различные коды |
| Псевдоцвета кода на карте | §5.14 | `EncoderCodeColorizer` | по статье |

**Отклонения:**

- **Режим сглаживания** (`LAYOUT_SMOOTH_PINWHEELS = True`). Его нет ни в статье, ни в продолжении. Карта выходит из многих пинвилов с плавными переходами, как ориентационная карта V1. На 60 000 цифрах глобальная энергия §5.5.1 хуже, чем в режиме статьи (0.273 против 0.220 от случайной расстановки), качество `Ē` одинаковое (0.98). Все замеры README сняты в этом режиме; переход на режим статьи — решение автора проекта.
- **Пустых ячеек 15 %, как в статье.** Прежнее значение 0.5 (запас для обменов) не дало выигрыша: голосование верхних деталей на 100/500 цифрах и карте до 5 000 точек — 65.2 % и 60.4 % при 0.5 против 64.0 % и 65.2 % при 0.15 (зёрна 0 и 1); соседи одного класса на уровне 3 — 0.441 и 0.489 против 0.463 и 0.485. Разница меньше разброса между зёрнами. Тест `test_default_empty_ratio_matches_space_filling_margin` проходит.
- **Ускоренные пути** (строки ненулевых `sim_λ`, знак вместо суммы, граница потенциала, почти-ничьи, скомпилированная выборка пар, слитое ядро) дают **тот же результат бит в бит**. Тесты сверяют их с прямыми, а по ходу раскладки пути сверяются с исходным проходом.

| λ_a = порог нижнего слоя детекторов | §7.1.11 | `LADDER_ACTIVATION_LAMBDA = "none"` | по статье |

**Отклонения:**

- **«Самая похожая точка зажигается всегда».** Без неё код окна, не похожий ни на одну точку сильнее λ_a, не оставил бы следа на карте.
- **Пороги слоёв в цикле.** Это равные шаги между квантилями попарных сходств кодов карты, теми же, которыми задан порог её раскладки (§7.1.7). На первом уровне выходит 0.39…0.53. В команде `layout` пороги 0.7…0.9.
- **Порог λ_a по §7.1.11 лучше квантилей.** Квантили 0.98 / 0.95 / 0.90 дали 31.4 / 44.6 / 55.0 %, правило статьи — 63.4 %. Замер снят на прежней сетке полей.

## Этап 6. Цикл

↺ **Конец цикла:** детали уровня снова идут на этап 2, пока окно не увидит цифру целиком.

| Понятие | Источник | Где в коде | Как сделано |
|---|---|---|---|
| Проход повторяется уровень за уровнем | §6.2, §6.6 | проход уровня `CycleStep` (`system/damp/cycle/step.py`), лестница `MnistLadderRunner` (`system/damp/cycle/ladder.py`) | по статье |
| Окно — миниколонка, память уровня общая для всех окон | П.2 | там же | по продолжению |
| Окна стоят плотно, на каждом элементе, и перекрываются | П.2, П.3 | `PlaneFieldBuilder(dense=True)` (`system/damp/cycle/plane_fields.py`) | по продолжению |
| Радиус окна — кластер похожих соседей и самый плотный круг | §6.4.1, §6.4.3 | там же | по статье; без §6.4.2 и §6.4.5 |
| Окно следующего уровня охватывает большую область | П.3 | правило роста в `KeyholeBuilder.build` (`system/damp/cycle/keyholes.py`) | доработка: во сколько раз, источники не говорят |
| В деталь входит 5–7 понятий | П.7 | `LADDER_CLUSTER_MIN_POINTS = 5` | по продолжению |
| Место в коде — внутри окна | §7.1.4.1, П.9 | `PositionBindingEncoder` | по статье и продолжению |
| Число уровней не задаётся | §6.6, П.7 | `LADDER_TOP_COVERAGE = 0.9` | доработка: остановка, когда окно видит ≥ 90 % углопозиций |
| Торможение соседних деталей | — | `LateralInhibition` (`system/damp/cycle/`), выключено | доработка, отвергнута замером |

**Отклонения:**

- **Правило роста окна — из физиологии зрения.** Радиусы окна меряются в том, что видит одна деталь уровня, поэтому окно на карте равно полю своей детали. Поле растёт в 2–2.5 раза от области к области (V1 → V2 → V4; Freeman & Simoncelli 2011, Rolls 2012). Замер: радиус поля 2.6 → 6.6 → 15.5 клетки. Окно одного размера на всех уровнях (§6.4.3 без правила) дало 34.4 % и падение узнавания с уровнем.
- **Без §6.4.2 и §6.4.5 при выборе окна.** Окно стоит на своём элементе, а поля соседних окон по П.2 обязаны перекрываться. Вытеснение оставляло 43 → 6.7 → 1 окно на картинку (16.6 %).
- **Торможение соседей** (0.5 и 0.25 поля) дало 33.8 % и 26.0 % — выключено.

## Сводка доработок

Чего нет ни в статье, ни в продолжении:

| Доработка | Где | Почему |
|---|---|---|
| Режим сглаживания раскладки (по умолчанию) | `LAYOUT_SMOOTH_PINWHEELS = True` | карта из многих пинвилов без складок; на нём сняты все замеры |
| Правило роста окна из физиологии зрения | `KeyholeBuilder.build` (`system/damp/cycle/keyholes.py`) | П.3 не говорит, во сколько раз |
| Самая похожая точка зажигается всегда | `LADDER_ACTIVATE_BEST` | у кода окна всегда есть след на карте |
| Маска по адресу бита | `LADDER_BINDING_MASK = "address"` | буквальный XOR насыщает код (10 %) |
| Пулинг "strongest" | `LADDER_BINDING_POOLING` | объединение переполняет код (49.8 %) |
| Остановка цикла по доле видимых углопозиций | `LADDER_TOP_COVERAGE` | число уровней не задаётся |
| Извлечение углопозиций | `MnistSobelAngleMap` | вне статьи: данные MNIST |
| Распознавание как мерка | `system/damp/decode/level_recognition.py` | вне статьи |

Ускоренные пути (раскладка, детекторы, окна, код окна, отбор сильнейших) дают тот же результат бит в бит, что прямые. Их сверяют тесты `SameResultFasterTest`, `MatrixClustersTest` и тесты раскладки.
